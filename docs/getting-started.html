Getting started

Lumen is in open beta. The fastest path from install to a working drive:

Requirements

  • macOS 12+, Linux (FUSE), or Windows (WinFsp runtime)
  • Rust toolchain (for the beta) — or grab a prebuilt release: Lumen-<version>.dmg from the releases page, containing all three binaries plus a first-run launcher. Install macFUSE first: brew install --cask macfuse. On Windows, unzip Lumen-<version>-win64.zip after installing WinFsp.
  • For S3 backends: your access key and secret key set as environment variables — never passed on argv

1. Build

From the prebuilt DMG: copy Lumen.app to /Applications and create ~/Library/Application Support/Lumen/lumen.env exporting LUMEN_INDEX_PATH, LUMEN_STORE_ENDPOINT, LUMEN_STORE_BUCKET, LUMEN_MOUNT_POINT, LUMEN_PASSWORD. Then open Lumen.app.

Or build from source:

git clone https://github.com/chasesdavis/lumen.git
cd lumen
cargo build --workspace

2. Mount a drive

The mount daemon starts, creates/opens the local index, and mounts the volume:

macOS / Linux

cargo run -p lumen-fuse-shim --bin lumen-mount -- \
  --mountpoint /Volumes/Lumen \
  --index-path ~/.lumen/index.db \
  --store-endpoint file://$HOME/.lumen/store \
  --bucket lumen-chunks

To use a real S3-compatible provider instead of the local dev backend, replace --store-endpoint file://... with your endpoint and export credentials first:

export LUMEN_S3_ACCESS_KEY_ID=...
export LUMEN_S3_SECRET_ACCESS_KEY=...
# R2: https://api.cloudflare.com/client/v4/accounts/<ACCOUNT>/r2
# B2/Storj/MinIO: your S3 endpoint
lumen-mount --mountpoint /Volumes/Lumen --index-path ~/.lumen/index.db \
            --store-endpoint https://... --bucket lumen-chunks

Windows

cargo run -p lumen-winfsp-shim --bin lumen-mount-winfsp -- ^
  --mountpoint C:\Lumen ^
  --index-path %USERPROFILE%\.lumen\index.db ^
  --store-endpoint file://%USERPROFILE%\.lumen\store ^
  --bucket lumen-chunks

3. Connect an agent (MCP)

Expose the drive to Cursor/Claude/Codex-type clients via the MCP server:

{
  "mcpServers": {
    "lumen": {
      "command": "lumen-mcp-server",
      "args": ["--transport", "stdio", "--index-path", "~/.lumen/index.db"]
    }
  }
}

With LUMEN_JWT_SECRET set, tool calls are gated behind the authorize tool (an Access-scope JWT). Without it the server runs in open mode.

4. Optional: run the API server

Auth, changelog feed, Dodo billing webhooks, usage metering, and the GC admin route:

export LUMEN_JWT_SECRET=$(openssl rand -hex 32)
export LUMEN_DODO_API_KEY=dodo_sk_...
export LUMEN_DODO_WEBHOOK_KEY=whsec_...

LUMEN_USERS_DB=~/.lumen/users.db \
LUMEN_USAGE_DB=~/.lumen/usage.db \
LUMEN_INDEX_DB=~/.lumen/server-index.db \
LUMEN_LOCAL_STORE_DIR=~/.lumen/store \
LUMEN_API_HOST=127.0.0.1 LUMEN_API_PORT=8080 \
cargo run -p lumen-api-server --bin lumen-api-server

Key endpoints:

  • POST /v1/auth/signup, POST /v1/auth/login
  • GET /v1/me — identity + plan state
  • GET /v1/changes?since=<cursor> — ordered mutation feed
  • POST /v1/files, POST /v1/files/delete
  • GET /v1/billing/usage — current-period storage/retrieved bytes
  • POST /v1/admin/gc — run one GC sweep; reclaimed bytes reduce the metered amount
  • POST /v1/dodo/webhook — Standard Webhooks signature verification

Troubleshooting

Mount fails on macOS with macFUSE not found
This beta's local kernel mount tests require a macOS FUSE box or CI runner. Use --store-endpoint file:// for non-FUSE development.
S3 store construction failed
Credentials must be exported as LUMEN_S3_ACCESS_KEY_ID and LUMEN_S3_SECRET_ACCESS_KEY. Never pass them as command-line arguments.
MCP tools return error -32001
The server is running gated mode. Call the authorize tool with an Access-scope JWT first; authorization persists for the connection.
GC reclaims nothing / reclaims too much
Every CommitBatcher feeding the index must flush before GC runs, or freshly uploaded chunks look like orphans. The MCP gc_run tool and the API admin route honor this flush-first contract automatically.
